# سامانه اسپرلوس — بک‌اند واقعی

این نسخه یک **سرور واقعی** دارد (نه فقط یک فایل داخل مرورگر). یعنی:

- هر مشاور از گوشی یا سیستم خودش، با نام‌کاربری/رمز خودش وارد می‌شود.
- به محض اینکه یک مشاور فایل یا مشتری‌ای اضافه/ویرایش کند، حداکثر تا ۶ ثانیه بعد در گوشیِ مدیر (و بقیه مشاوران) هم دیده می‌شود.
- اطلاعات روی یک سرور مرکزی نگه‌داری می‌شود، نه روی گوشیِ یک نفر.

## محتویات پوشه
```
server.js       ← کد سرور (کار می‌کند با: حالت فایل روی دیسک، یا حالت MongoDB رایگان)
package.json
public/index.html  ← خود برنامه (چیزی که در مرورگر باز می‌شود)
data/data.json  ← فقط در «حالت فایل» بعد از اولین اجرا خودش ساخته می‌شود
```

## تست روی سیستم خودتان (قبل از هر چیز)
1. Node.js را از nodejs.org نصب کنید (نسخه ۱۸ به بالا).
2. داخل این پوشه، در ترمینال/CMD بنویسید:
   ```
   node server.js
   ```
3. در مرورگر بروید به: `http://localhost:3000`
4. چون اولین بار است، صفحه «راه‌اندازی اولیه» می‌آید و یک حساب مدیر می‌سازید.

این حالت (بدون تنظیم `MONGODB_URI`) فقط روی همان سیستم شما کار می‌کند و اطلاعات را در `data/data.json` نگه می‌دارد. برای اینکه همه مشاوران از گوشی خودشان (حتی بیرون از دفتر) وصل شوند، باید سرور را **آنلاین/میزبانی (host)** کنید — یکی از راه‌های زیر را انتخاب کنید.

## گزینه ۱ (رایگان و واقعی): Render + MongoDB Atlas
این ترکیب کاملاً رایگان است و نیاز به کارت بانکی ندارد. نکته‌ی فنی مهم: نسخه‌ی رایگان Render دیسکش بین خاموش/روشن‌شدن‌ها پاک می‌شود (این را از مستندات خودشان بررسی کردم)، پس به‌جای ذخیره روی دیسک سرور، از یک دیتابیس رایگان و همیشگی (MongoDB Atlas) استفاده می‌کنیم. این سرور از قبل برای هر دو حالت آماده است.

**قدم ۱ — ساخت دیتابیس رایگان (MongoDB Atlas):**
1. در `cloud.mongodb.com` ثبت‌نام کنید (نیازی به کارت بانکی نیست).
2. «Build a Database» → گزینه‌ی **M0 (Free)** را انتخاب کنید → منطقه و ارائه‌دهنده هرچه بود مهم نیست → بسازید.
3. یک Database User با نام‌کاربری/رمز بسازید (رمز را جایی یادداشت کنید).
4. در بخش Network Access، گزینه‌ی «Allow access from anywhere» (`0.0.0.0/0`) را بزنید.
5. روی «Connect» → «Drivers» کلیک کنید و رشته اتصال (Connection String) را کپی کنید؛ چیزی شبیه این:
   `mongodb+srv://myapp-user:PASSWORD@cluster0.xxxxx.mongodb.net/`

**قدم ۲ — آپلود کد در گیت‌هاب (بدون نیاز به خط فرمان):**
1. در `github.com` یک حساب رایگان بسازید.
2. یک مخزن (Repository) جدید بسازید، مثلاً با نام `esperlous-app`.
3. داخل صفحه‌ی مخزن، «Add file → Upload files» را بزنید و فایل‌های `server.js`، `package.json`، `README.md` و پوشه‌ی `public` (با `index.html` داخلش) را بکشید و رها کنید → Commit.

**قدم ۳ — دیپلوی روی Render:**
1. در `render.com` ثبت‌نام کنید (با گیت‌هاب هم می‌شود).
2. «New +» → «Web Service» → مخزن `esperlous-app` را انتخاب کنید.
3. Build Command: `npm install` — Start Command: `npm start` (پلن Free را نگه دارید).
4. در بخش Environment Variables یک متغیر اضافه کنید:
   - Key: `MONGODB_URI`
   - Value: همان رشته‌ی اتصالی که از Atlas کپی کردید (رمز را هم داخلش جایگزین کنید)
5. «Create Web Service» را بزنید و چند دقیقه صبر کنید.
6. آدرسی شبیه `https://esperlous-app.onrender.com` به شما داده می‌شود — همین را در مرورگر باز کنید تا صفحه‌ی «راه‌اندازی اولیه» بیاید.
7. برای اطمینان از وصل‌بودن درست به دیتابیس، آدرس `.../api/health` را باز کنید؛ باید ببینید: `{"ok":true,"backend":"mongo"}`. اگر `"backend":"file"` نشان داد، یعنی متغیر `MONGODB_URI` درست تنظیم نشده.

⚠️ **تنها محدودیت واقعی این گزینه‌ی رایگان:** اگر برنامه ۱۵ دقیقه هیچ استفاده‌ای نشود، Render آن را می‌خواباند؛ اولین باز شدن بعد از خواب حدود ۳۰ تا ۶۰ ثانیه طول می‌کشد (فقط یک بار، بعدش سریع است). داده‌ها این وسط از بین نمی‌روند چون در MongoDB Atlas (نه دیسک Render) ذخیره شده‌اند.

⚠️ **نکته درباره دسترسی از ایران:** هم Render و هم MongoDB Atlas سرویس‌های خارجی‌اند. من نمی‌توانم همین الان تضمین کنم وضعیت فیلترینگ/تحریم برایشان از داخل ایران چطور است چون ممکن است تغییر کند — بهتر است قبل از اعتماد کامل، از داخل ایران (بدون فیلترشکن) تست کنید. اگر مشکلی بود، گزینه ۲ (لیارا) جایگزین مطمئن ایرانی است.

## گزینه ۲ (پولی ولی مطمئن‌تر برای ایران): لیارا (Liara)
لیارا یک سرویس ایرانی است که مستقیم و بدون فیلترشکن در دسترس است.
1. در `liara.ir` ثبت‌نام کنید.
2. یک «اپلیکیشن» جدید از نوع **Node.js** بسازید.
3. پوشه‌ی پروژه (همین فایل‌ها) را zip کنید و در کنسول لیارا، تب Drag & Drop، آپلود کنید.
4. حتماً از بخش «دیسک»، یک دیسک بسازید و به مسیر پروژه وصل کنید (چون این سرور در حالت فایل کار می‌کند، اگر `MONGODB_URI` تنظیم نکنید).
5. استقرار را بزنید؛ یک آدرس HTTPS رایگان مثل `esperlous.liara.run` می‌گیرید.

## گزینه ۳: یک سرور مجازی (VPS) خارج از ایران + PM2
اگر سرویس خارجی می‌خواهید (مثل یک VPS ساده از هر شرکتی):
```
# روی سرور:
sudo apt update && sudo apt install -y nodejs npm
npm install -g pm2
pm2 start server.js --name esperlous
pm2 startup && pm2 save   # تا با ری‌استارت سرور، برنامه خودش دوباره بالا بیاید
```
سپس یک دامنه/ساب‌دامنه به آی‌پی سرور وصل کنید و با Nginx + Certbot گواهی HTTPS رایگان بگیرید (HTTPS لازم است، وگرنه دکمه «کپی مشخصات» و بعضی امکانات مرورگر روی گوشی درست کار نمی‌کنند).

## گزینه ۴: اجرا روی یک سیستم داخل خود دفتر (ساده‌ترین، ولی محدود)
اگر فقط می‌خواهید داخل دفتر و روی وای‌فای مشترک تست کنید:
1. `node server.js` را روی یک سیستم دفتر اجرا کنید (باید همیشه روشن بماند).
2. آی‌پی محلی آن سیستم را پیدا کنید (مثلاً `192.168.1.5`).
3. مشاوران داخل همان وای‌فای، آدرس `http://192.168.1.5:3000` را باز می‌کنند.
⚠️ این حالت فقط داخل شبکه دفتر کار می‌کند؛ مشاوری که بیرون از دفتر با اینترنت موبایل باشد به آن دسترسی ندارد.

## نکات مهم امنیتی و نگهداری
- **پشتیبان‌گیری:** جدا از دکمه «بک‌آپ» داخل برنامه (که فقط اطلاعات خودِ همان مشاور را دانلود می‌کند)، بهتر است هر چند روز یک‌بار از کل داده‌ها یک نسخه پشتیبان بگیرید:
  - در «حالت فایل» (لیارا/VPS/دفتر): از فایل `data/data.json` کپی بگیرید.
  - در «حالت MongoDB» (Render رایگان): از پنل Atlas → Cluster → «...» → «Back Up» می‌توانید بک‌آپ دستی بگیرید (رایگان هم هست).
- برای بررسی سریع اینکه سرور به‌درستی بالا آمده و به دیتابیس وصل است، آدرس `/api/health` را باز کنید.
- رمزهای عبور روی سرور به‌صورت هش‌شده (scrypt) ذخیره می‌شوند، نه متن ساده.
- برای امنیت بیشتر، حتماً از HTTPS استفاده کنید (هم Render و هم لیارا این را خودکار می‌دهند).
- اگر یک مشاور دیگر در دفتر کار نمی‌کند، از پنل «مدیریت حساب مشاوران» حسابش را حذف یا رمزش را عوض کنید.
- ظرفیت این نسخه برای یک دفتر با تعداد محدود مشاور (مثلاً تا حدود ۲۰-۳۰ نفر) کاملاً مناسب است. اگر دفتر بزرگ‌تر شد یا حجم عکس‌های قرارداد خیلی بالا رفت (نسخه‌ی رایگان Atlas سقفش ۵۱۲ مگابایت است)، باید یا به پلن پولی Atlas ارتقا دهید یا از یک دیتابیس واقعی‌تر استفاده کنیم — بگویید تا آن ارتقا را هم انجام دهم.
